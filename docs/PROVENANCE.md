# 来源与整理记录

## 提取来源

- `eyehandwork_raw_backup/calibration_scripts/`：四个原始检测、采集、求解、验证脚本。
- `eyehandwork/runtime/publish_handeye_tf.py`：静态 TF 发布脚本。
- `eyehandwork/results/`：最终标定和独立验证报告。
- `eyehandwork_raw_backup/data/samples/metadata/`：选取原始编号 1–93 的元数据，用于复现最终迁移包的结果。

备份共 181 份样本。本包依据最终报告的 43 组求解样本、10 组独立验证样本选择相应区间；后续扩展实验和旧结果保留在原始备份，不混入默认示例。没有删除或改写原始目录。

示例 JSON 仅移除了 `image_file`、`overlay_file` 两个指向未分发图像的路径；位姿、时间戳、相机内参和板参数保留。原始独立验证报告的绝对机器路径改为仓库内参考路径。元数据足以复现求解，不足以重新计算图像角点。

## 保留行为

- ROS 标准图像、内参与 TCP 位姿输入接口。
- 固定 ChArUco 板、眼在手上的变换方向。
- OpenCV 五种手眼算法以及默认 Park 选择策略。
- 原求解和验证的误差定义（README 说明了不同旋转参考）。
- 操作者停稳后按键采集，程序不控制机械臂。

## 为独立复用所做的修改

- 新增中文 README、依赖清单、忽略规则、回归测试和 GitHub Actions 配置。
- 将重复的实物板定义集中到 `config/board.yaml`，检测和采集共享配置；补充 DetectorParameters 新旧接口兼容分支。
- 求解与验证默认使用同一结果路径、88 个角点、0.05 秒筛选阈值。
- 求解前检查有限数值和刚体矩阵，排除损坏样本；拒绝明显退化的旋转样本和无效算法输出，全部失败时给出明确错误。
- 验证同样检查时间差及无效样本，报告求解/验证编号交集供检查来源。
- 采集拒绝零时间戳、过期图像、重复图像，检查图像写入结果。
- 静态 TF 显式要求结果路径，从矩阵统一导出平移和旋转，避免读取不一致的冗余字段。

## 验证范围

2026-10-05，本地 Python 3.10 / OpenCV 4.5.4 环境：

- 五项自动化测试通过：已知真值合成数据恢复、退化运动拒绝、无效输入过滤、原始板几何检查、真实样本命令行求解与独立验证。
- 真实求解结果与原始最终矩阵数值一致，独立验证复现 RMS 1.861178 mm / 0.184893°。
- 全部脚本语法检查通过；ROS 2 Humble 下采集、检测和 TF 脚本命令行与模块导入检查通过。
- 没有连接硬件，没有在本次整理中重新采集图像、驱动机械臂或发布 TF。GUI、现场话题 QoS、时间同步及 TF 树仍需在目标机器检查。
- GitHub Actions 配置已加入，但未上传运行。较新 OpenCV 的兼容分支未经过实机图像验证。

## 发布边界

这是脚本式独立仓库，直接运行 `python3 scripts/<工具>.py`，不需要 colcon 构建。没有打包其他项目的机器人驱动、FoundationPose、模型权重、Conda 环境或采集图像。没有初始化嵌套 Git 仓库或上传 GitHub。
